Pooled Node Storage
  • Transforms, states and metadata each get their own pool instead of one struct per node.
    •  
  • Every node is referenced by a single 64-bit handle, with the pool index and slot index packed into it.
    •  
  • Deleted slots get reused rather than freed. The factory also tracks how many nodes it has handed out and taken back.
Hierarchy Resolution
  • Parenting, unparenting and connecting all take arrays, so an entire scene can be relinked in one call.
    •  
  • Resolving runs over the whole tree, or just the branches that actually moved.
    •  
  • Sphere bounds can be rebuilt during the same pass. Without that, the spatial queries go stale the moment a transform changes.
Spatial and Metadata Queries
  • Nodes can be searched against a frustum, sphere, AABB, OBB or capsule.
    •  
  • Each search takes a metadata mask, so you only get back the nodes you actually asked for.
    •  
  • Parent, child and sibling searches walk the full hierarchy and return every match, not just the immediate one.
Threading
  • Pool access goes through a shared lock. Readers run together, writers get the pool to themselves.
    •  
  • The tree walk keeps its scratch buffers thread-local, so workers aren't fighting over the same memory.
