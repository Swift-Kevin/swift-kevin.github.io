Component Reflection
  • Components declare themselves through a macro that registers the name against its type before main ever runs.
    •  
  • The Components panel reads straight from that map, so a new component turns up in the editor without the UI knowing anything about it.
    •  
  • Each registration prints on startup, which makes it obvious when something never got pulled into the build.
Entity Hierarchy
  • The Entities panel rebuilds the parent and child tree each frame from the parent ID stored on every Transform.
    •  
  • Anything without a valid parent counts as a root, and the panel draws down from there recursively.
    •  
  • Every row is labelled with the entity name and its raw ID, which makes lining it up against the Inspector straightforward.
Reparenting
  • Rows in the tree are both drag sources and drop targets, so an entity is reparented by dragging it onto another one.
    •  
  • Here Saturn has been dropped under Mars, and Jupiter under one of Saturn's own moons. Nonsense astronomically, but it proves the links rebuild wherever you put them.
    •  
  • Orbits follow whatever they are attached to, so a moved planet takes its moons with it.
Transforms
  • Each entity builds its own local matrix from translation, rotation and scale.
    •  
  • Rotation is composed one axis at a time in radians, then multiplied together as pitch, yaw and roll.
    •  
  • Gateware's math library does the work here, which kept the tool consistent with the rest of my Gateware projects.
Console and Diagnostics
  • Log entries carry a severity of Debug, Warning or Error, each with its own checkbox filter.
    •  
  • Entries live in the registry's context, so any system can log without being handed a pointer to the console.
    •  
  • Severity also drives the text colour, so an error stays findable in a long list.
